# ADR-013: DB 전환 승인 전에 그림자 리허설로 대상 응답을 관찰한다

- Status: Accepted — 구현된 결정을 기록, 2026-11-08 (PR #365, #366)
- Tracking: Issue #362(PR #365), Issue #363(PR #366), PR #369, [티켓 83-shadow-mirror](../../tickets/provisioning/83-shadow-mirror.md), [84-shadow-gate](../../tickets/provisioning/84-shadow-gate.md)
- 관련: [ADR-006](./ADR-006.md)(Envoy 중계), [ADR-010](./ADR-010.md)(DB 전환), [ADR-004](./ADR-004.md)(Claude 비용 상한), [이벤트 안내서](../engineering/events-guide.md) `shadow.*`

## 배경

결승 데모의 순서는 데이터 복제(CDC), DB 전환(두 번째 승인, PgBouncer), 트래픽 전환(중계 Envoy 가중치), 완료다(티켓 83). DB 전환을 승인하는 사람은 그 전에 대상이 원본과 같은 답을 하는지 볼 근거가 없었다. 티켓 83, 84는 복제가 따라잡은 뒤 DB 전환 승인 전에, 중계 Envoy로 들어온 실제 GET을 대상에도 보내 비교하는 단계를 만들었다. 티켓은 둘 다 상태를 `IN_REVIEW`로 적고 있으나 PR #365, #366은 2026-11-07(UTC)에 병합됐다.

## 결정

1. **중계 Envoy가 GET만 복사한다(티켓 83 S1, S2).** 켜면 허용 경로마다 `match.prefix`와 `:method == GET` 헤더 조건 라우트를 `/` 바로 앞에 두고, `request_mirror_policies`로 정적 클러스터 `cluster_shadow`(127.0.0.1:18090)에 복사본을 보낸다. 사용자 응답 경로와 가중치는 그대로이고 복사본 응답은 Envoy가 버린다. 허용 목록은 기본 거부이며, 빈 목록, `/`로 시작하지 않는 경로, `/`·`/admin`·`/__cmp`와 겹치는 경로는 거절한다.
2. **수집기가 3-way diff를 한다(S5).** `cmp_traffic.shadow` 수집기는 복사본마다 원본에 GET을 두 번, 대상에 한 번 보낸다. 상태 코드, JSON pointer 잎으로 편 본문, 지연을 비교한다. 원본 두 응답 사이에 달라진 pointer는 잡음으로 배우고 실행 전체에 소급한다. JSON이 아니면 본문 sha256으로 비교한다.
3. **부하와 보관을 제한한다(S7, S8, S9).** 원본 재요청은 초당 `rate_per_sec`(2~100) 상한이고, 실행은 900초가 지나면 스스로 멈춘다. 본문은 해시만 남기고, 불일치 표본은 쿼리 문자열을 빼고 값을 형식과 크기로 가려 최대 20개까지 둔다. 수집기와 제어 API는 루프백에만 연다.
4. **Activity는 릴레이 큐에 둔다.** `shadow_start`, `shadow_summary`, `shadow_stop`(`cmp_worker.activities.traffic_shadow`)은 Envoy와 같은 호스트의 릴레이 워커가 처리한다(ADR-006 릴레이 워커).
5. **데이터 Workflow가 관찰하고 판정한다(티켓 84).** `DataMigrationWorkflow`는 streaming에 도달한 뒤, PgBouncer 설치 대기·`dm_route_app`·첫 전환 계획 알림 전에 관찰 창(`window_s`, 기본 180초)을 연다. 감시 주기마다 `dm_sample`로 복제를 확인하고 `shadow_summary` 뒤 `shadow.progress`를 낸다.
   - 판정(`cmp_data.shadow.judge`): 수집 실패나 시작 거절은 `skipped`(`SHADOW_UNAVAILABLE`), `compared < min_requests`(기본 50)는 `skipped`(`SHADOW_NO_TRAFFIC`), 관찰 중 복제가 streaming을 벗어나면 `stopped`(`SHADOW_STOPPED_REPLICATION`), `match/compared >= pass_ratio`(기본 0.99)이고 `target_5xx == 0`이면 `pass`, 그 밖은 `warn`이다.
   - `shadow_stop`은 `finally`에서 항상 부른다. 불일치가 있으면 `shadow_explain`(Provisioning 큐, ADR-004의 `build_llm_factory`)이 설명을 붙이고, 실패하거나 20초를 넘으면 `ai=null`이다.
6. **관찰 전용이다.** 결과는 `shadow.result` 이벤트와 `cutover.plan.preconditions`의 `shadow` 줄로만 남는다. 이 줄은 전환 준비 판정(`plan_ready`)에 넣지 않는다. 자동 차단, 자동 수정, DB 설정 변경, 쓰기 복사, 운영 Pod 재시작은 하지 않는다.
7. **기본은 꺼짐이다.** 입력 `data_migration.shadow.enabled`가 켜졌을 때만 `workflow.patched("shadow-rehearsal-v1")`을 부르고, 부모가 자식에 `shadow`와 `relay_queue`를 넘긴다. 꺼지면 Activity 순서, 이벤트, 자식 입력이 이전과 같고, `shadow=None`의 라우트 출력은 바이트 단위로 같다.

## 이유

- **GET만 복사하는 이유:** 수집기는 복사본을 원본에 두 번 다시 보낸다. 쓰기 요청을 복사하면 원본에 같은 쓰기가 더 일어나고, 대상에도 쓰기가 들어간다. 데모 앱의 `POST /api/messages`는 INSERT이며 `:method == GET` 조건으로 복사되지 않음을 Envoy v1.32에서 확인했다(티켓 83). GET이라도 부작용이 있을 수 있어 허용 경로를 기본 거부로 두고, 권장 경로(`/api/messages`, `/api/stats`)는 핸들러가 SELECT만 하는지 코드를 읽어 골랐다.
- 원본을 두 번 부르면 시각이나 요청 ID처럼 매번 바뀌는 필드를 잡음으로 걸러, 대상만 다른 값을 불일치로 남길 수 있다.
- 리허설은 승인하는 사람에게 근거를 보여 주는 목적이다. 판정이 전환을 막지 않게 해서 리허설 실패가 이전을 멈추지 않게 했다(티켓 84 D7).

## 결과와 위험

- **ADR-006과의 관계:** 그림자 리허설은 DB 전환 전에 끝나고, 트래픽 가중치 전환의 통과 조건이나 롤백 기준에 들어가지 않는다. `EnvoyProxy.set_shadow`는 지금 라우트의 가중치를 그대로 두고 복사 설정만 바꾼다. 가중치 Activity는 복사를 몰라서, 켜진 채 가중치를 바꾸면 복사가 꺼진다(티켓 83 S4, 안전한 쪽). Workflow는 DB 전환과 트래픽 단계 전에 `shadow_stop`을 부른다.
- 원본 재요청은 사용자 트래픽 위에 더해지는 부하다. 비교 1건에 원본 2번이므로 기본 `rate_per_sec` 20이면 비교는 초당 10건까지다.
- 쓰기가 계속되는 중에는 원본과 대상의 조회 시점이 달라 `/api/stats` 같은 집계가 불일치로 보일 수 있다(티켓 83).
- `p99_ratio`는 이벤트에만 싣고 판정에는 쓰지 않는다(`judge`).
- `cluster_shadow`를 bootstrap에 더하려면 `infra/relay/enable-shadow.sh`로 Envoy를 한 번 재시작해야 한다. 중계 서버 반영과 데모 리허설 실측은 티켓 83, 84에서 미완료로 남아 있다. 그 뒤 실제로 반영했는지는 확인하지 않음.
- 웹 화면(티켓 85)의 구현 상태는 확인하지 않음.

## 대안(검토했거나 남겨 둔 것)

- 복사 설정을 CDS 파일에 두기: 릴레이 워커(`set_target`)가 CDS 파일을 `cluster_target` 하나로 덮어써서 쓰지 않았다(티켓 83 S3).
- 수집기 주소를 별도 설정으로 두기: Envoy와 어긋날 수 있어, 켤 때 `/config_dump`에서 원본·대상 주소를 읽는다(S6).
- `apps/api` agent_chat으로 AI 설명: HTTP 경로라 Workflow에서 부를 수 없어 `shadow_explain` Activity를 새로 두었다(티켓 84 D10).
- 판정으로 전환을 막는 게이트: 티켓의 절대 원칙(자동 차단 없음)으로 쓰지 않았다.
