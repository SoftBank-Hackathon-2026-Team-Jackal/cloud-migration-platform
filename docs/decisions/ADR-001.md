# ADR-001: Temporal as the orchestration scaffold

- Status: Accepted for this repository's initial scaffold
- Date: 2026-11-02

## Context

Migration spans analysis, build, approval, provisioning, data transfer, and traffic switching. The team wants a concrete Workflow example to learn Temporal. The earlier architecture snapshot left the asynchronous execution technology open; the supplied platform stack proposes Temporal.

## Decision

Use one `MigrationWorkflow` with separate Activity Task Queues. API sends approval and cancellation Signals and reads status by Query. Local Activities remain inert examples until their contracts and safety conditions are defined.

## Consequences

Temporal Server and its own persistence are local dependencies. Workflow code must remain deterministic; real external work belongs in Activities. The deployment topology and production retry/heartbeat policies remain future decisions.

## Alternatives

Queue and worker orchestration or Kubernetes Jobs were considered in the earlier architecture snapshot but were not selected for this scaffold.
