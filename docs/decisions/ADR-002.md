# ADR-002: P0 Provisioning 범위와 병렬 작업 경계

- Status: Accepted — 사용자 합의, 2026-11-03
- Tracking: [Issue #7](https://github.com/SoftBank-Hackathon-2026-Team-Jackal/cloud-migration-platform/issues/7)
- 기존 ADR-001의 Temporal 학습 스캐폴드 결정을 대체하거나 전체 플랫폼 스택 채택 ADR로 사용하지 않는다.

## 배경

01의 입력 검증 이후 02/05/06/07을 병렬 구현하려면 공유 계약과 수정 파일을 먼저 고정해야 한다. 사용자는 P0 구현 범위를 축소하되 실제 생성 전 Preview·승인은 유지하기로 했다. 이 ADR의 결정은 목표 정책이며, 공통 코드나 승인/Plan 실행이 이미 구현됐음을 뜻하지 않는다.

## 결정

1. 동일 Plan ID의 수정은 증가하는 Revision으로 관리한다. 게시한 Revision 내용은 불변이며 변경 시 새 Preview·승인이 필요하다.
2. Preview·사용자 승인을 유지한다. 최소 Preview는 대상, 생성/변경 자원, 주요 사양·기본값, 오류/경고, 계획·산출물 식별을 제공한다. UI 배치가 미정이어도 서버의 승인 정합성을 생략하지 않는다.
3. ArtifactRef/Digest는 핵심 산출물부터 적용한다: 검증 소스와 최종 이미지의 연결, Spec, 저장 Terraform Plan, 실행할 Chart/Values·동적 바인딩 규칙. 로그/모든 중간 파일을 범용 산출물 플랫폼으로 만들지 않는다. 실행 범위에서 필요한 산출물이 빠진 계획은 승인 불가다.
4. 공통 기반은 Sandbox/Provisioning Chart 입출력, 최소 Plan/Preview/Artifact 계약, Digest 계산 및 검증 fixture에 한정한다. 범용 저장소·이벤트 프레임워크는 이번 준비 범위에서 제외한다.
5. DB와 App은 별도 Chart/Release로 구성한다. 같은 DB Chart를 Sandbox/Production에서 다른 Values로 사용한다. StorageClass와 Secret 이름·키 참조를 명시하며 운영 비밀번호를 Values에 직접 싣지 않는다.
6. AWS/GCP 기존 네트워크 재사용은 P0에서 제외한다. 신규 네트워크·클러스터 구성이 대상이다. ON_PREM의 기존 K3s 사용은 유지한다. 원본 AWS EKS 조회와 플랫폼의 사전 준비된 State 저장소는 이 제외 대상이 아니다. 데모에서 사전 생성한 자원을 재사용하려면 신규 생성 경로와 구분해 후속 합의한다.
7. Terraform State는 중앙 S3에 환경별 key로 분리하고 잠금을 사용한다. 같은 대상 환경의 Revision마다 별도 State를 만들지 않는다. Terraform 버전·잠금 설정·접근 권한과 실제 버킷은 05/06의 공통 실행 설정으로 확정한다. Preview가 Backend 인프라를 생성하지 않는다.
8. 승인 API는 특정 Plan ID·Revision·Digest를 대상으로 하고, 인증된 승인자와 작업 권한을 확인한다. 정확한 URL/인증 연동은 07 착수 조건이며 여기서 임의 확정하지 않는다.
9. DB 승인 기록은 유지한다. 범용 Outbox는 P0에서 보류한다. 승인 기록 후 Temporal Signal을 전달하며, 요청 재시도/재전달·상태 조회로 DB 성공/전달 실패를 복구한다. 승인 이벤트 ID와 실행 단계 상태를 통해 중복 실행을 억제하고 실행 직전에 DB 승인 기록·Revision·Digest를 재확인한다. API 접수와 Workflow 실행은 별도 상태다. 재전달 후 영구적인 전달 실패를 숨기지 않는다.
10. 02는 실제 Helm 렌더, 05/06은 Terraform 정적 검사와 격리 계정의 실제 저장 Plan, 07은 테스트 DB/Temporal와 안전한 가짜 실행기를 기준으로 완료를 판정한다. 실행하지 못한 필수 검증은 미검증/차단으로 남긴다.

## 결과와 구현 구분

Issue #7은 위 정책 문서화와 EXISTING 모드의 P0 거절을 구현한다. 01의 기존 입력 형태는 읽을 수 있지만 공개 Planning/Adapter가 `UNSUPPORTED_P0_NETWORK_MODE`로 거절한다. 기존 정상 CREATE 및 ON_PREM 경로는 유지한다.

공통 기반 구현은 [CP-01](../../tickets/provisioning/cp-01-shared-contracts.md)이 담당한다. 이것이 main에 반영되고 동일 기준 커밋을 사용할 수 있기 전에는 02/05/06/07을 네 개의 쓰기 작업으로 동시에 시작하지 않는다. 정책 합의 완료와 공통 구현 완료를 구분한다.

## 미정 사항

- 실제 최소 Preview 화면, 승인 URL/인증 주체·권한 연동, 인증 실패/권한 없음 응답 계약.
- AWS/GCP Node·네트워크/아웃바운드 프로필, 리전·계정/프로젝트·권한과 실제 저장 Plan 검증 환경.
- S3 Backend 접근·잠금의 실제 설정 및 Terraform/Provider 버전 고정.
- Sandbox 정리 실패의 운영 진행 정책, Secret 저장 제품·회전, 자동 자원 정리.

위 미정 사항은 해당 티켓의 의존 작업으로 명시하며 임의 기본값을 운영 정책으로 간주하지 않는다. [병렬 작업 규칙](../../specs/provisioning/parallel-work.md)에 파일 소유권과 통합 순서를 정의한다.

## 개발 진행 방식 변경 (2026-11-03, #9)

사용자 후속 지시로 병렬 진행 계획을 중단하고 한 티켓씩 순차 구현한다. P0 제품 정책·승인·State 결정은 유지한다. CP-01은 후속 기능이 실제로 소비하는 최소 공유 코드 구현으로 진행하고, 병렬 worktree/공유 파일 담당 준비를 완료 조건으로 두지 않는다. 필요한 문서는 구현 이슈/PR에 포함하며 문서만을 위한 이슈/PR을 기본적으로 생성하지 않는다.
