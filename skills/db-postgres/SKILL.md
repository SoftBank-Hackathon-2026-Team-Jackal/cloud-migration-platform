# db-postgres

## 언제 쓰는지
PostgreSQL 사용 방식을 매핑할 때 쓴다: 버전, 확장, 연결 변수, 세션 기능(advisory lock, LISTEN/NOTIFY), 마이그레이션 실행 방식. 근거는 코드 스캔, SQL 스캔, 매니페스트 스캔 결과다.

## 조사 절차
1. 매니페스트의 PostgreSQL 이미지와 태그에서 주 버전을 확인한다. 요구사항은 16만 지원한다.
2. `CREATE EXTENSION` 탐지 결과를 확인한다. 하나라도 있으면 해당 기능은 `NONE`이고 필수면 차단이다.
3. 연결 설정이 필드별 변수인지 단일 URL 변수인지 확인한다. 단일 URL은 현재 계약으로 바인딩할 수 없다.
4. 코드에서 advisory lock, LISTEN/NOTIFY, 커넥션 풀러(PgBouncer) 가정을 찾는다.

## 판단 기준
- 확장 없이 PostgreSQL 16 Pod를 쓰면 `DIRECT`.
- 원본이 RDS 같은 관리형이면 백업·장애 조치를 잃으므로 `PARTIAL`이다.
- 버전이 16이 아니면 요구사항을 만들지 못하므로 차단 사유로 보고한다.
- 영속 데이터 저장은 보통 필수 기능으로 제안한다.

## 대상별 차이
- AWS·GCP·ON_PREM 모두 클러스터 안 Pod로 옮긴다. 이미지는 대상 구성 단계에서 정한다.

## 수정 패턴
- 필드별 변수로 연결을 바꾸는 코드 수정은 계약이 URL 출력을 지원하지 않을 때의 대안이다. 먼저 플랫폼 쪽 해결을 확인한다.
- 마이그레이션이 확장을 만들면 확장 없는 대안이 있는지 근거와 함께 제안한다.

## 테스트 패턴
- 쓰기 후 읽기가 일치하는지 확인한다.
- DB Pod를 재시작한 뒤 데이터가 유지되는지 확인한다.
- 앱에서 DB 5432로의 연결이 성공하는지 확인한다.
