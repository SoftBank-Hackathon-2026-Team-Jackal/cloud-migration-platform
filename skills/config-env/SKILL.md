# config-env

## 언제 쓰는지
`.env`와 코드가 읽는 환경 변수를 대조하고, 원본 환경에 묶인 변수의 제외·대체와 비밀 분류를 정할 때 쓴다. 분석 단계는 변수 이름만 다룬다. 값은 읽지 않는다.

## 조사 절차
1. 코드 스캔의 환경 변수 읽기와 `.env` 이름을 대조해 "`.env`에만 있음"과 "코드가 읽지만 `.env`에 없음"을 나눈다.
2. 대조가 부분 스캔(`partial`)이면 "안 쓰는 변수" 결과를 신뢰하지 않는다.
3. `AWS_` 접두사 변수는 원본 환경에 묶인 변수로 보고 제외 후보로 둔다.
4. DB 연결 변수는 요구사항의 `env_bindings`로 대체할 수 있는지 확인한다.

## 판단 기준
- 일반 설정 변수는 `.env` 참조로 그대로 주입한다(`DIRECT`).
- 원본 환경에 묶인 변수는 제외하거나 대체해야 하므로 `API_DIFF`.
- 이름에 PASSWORD·SECRET·TOKEN·KEY가 들어가면 비밀로 분류하고 값은 기록하지 않는다.
- 코드가 필수로 읽는데 `.env`에 없으면 누락으로 보고한다.

## 대상별 차이
- 대상에 따라 달라지는 변수는 없다. 원본 환경에 묶인 변수만 제외·대체한다.

## 수정 패턴
- 누락 변수: 사용자에게 값을 요청하는 항목으로 보고한다. 값을 추측하지 않는다.
- DB 연결 변수: 필드별이면 각 출력으로, `*_URL`·`*_URI` 단일 변수면 `connection_url_secret_ref` 출력으로 바인딩해 대체한다. key=value DSN은 표현할 수 없어 보고만 한다.

## 테스트 패턴
- 필수 변수가 모두 주입된 상태로 앱이 시작하는지 확인한다.
- 제외한 변수가 없어도 앱이 시작하는지 확인한다.
