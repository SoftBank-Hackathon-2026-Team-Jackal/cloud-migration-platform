# network

## 언제 쓰는지
통신 규칙(앱 ↔ DB, 외부 호출)과 외부 진입(Ingress, ALB)을 매핑할 때 쓴다. 근거는 코드의 외부 호스트 호출, 매니페스트의 Ingress, 인프라 스캔의 보안 그룹이다.

## 조사 절차
1. 코드의 문자열 상수 외부 호스트 호출을 모은다. 변수로 만든 주소는 정적 스캔이 놓치므로 미확인 위험으로 적는다.
2. 앱 → DB 연결은 리소스 간 통신으로, 외부 호출은 `external_host` 통신 의도 후보로 둔다.
3. Ingress의 ALB 어노테이션과 클래스를 확인해 외부 진입(프로토콜·포트·대상)을 기록한다.
4. 각 외부 목적지가 이전 대상인지 원본에 남길 것인지(`MIGRATE`/`KEEP`) 구분한다.

## 판단 기준
- 통신 의도는 NetworkPolicy로 그대로 옮길 수 있으면 `DIRECT`.
- ALB 전용 어노테이션은 대상별로 바꿔야 하므로 `API_DIFF`.
- 의도에 없는 외부 호출은 Sandbox에서 차단되므로 누락되면 실패한다. 후보를 빠짐없이 올린다.
- 대상 CIDR·보안 그룹 ID는 의도에 넣지 않는다.

## 대상별 차이
- AWS: ALB 어노테이션을 그대로 쓴다.
- GCP: GKE Ingress 방식으로 바꾼다.
- ON_PREM(K3s): 기본 Ingress 컨트롤러(Traefik) 방식으로 바꾼다.

## 수정 패턴
- 통신 의도 누락: 외부 호스트·포트·프로토콜을 의도에 추가하고 같은 Sandbox를 갱신한다(빌드 없음).
- 외부 진입은 요구사항 의도에 자리가 없으므로 분석 결과에 기록한다(D-15).

## 테스트 패턴
- 앱에서 DB로의 연결이 성공한다.
- 의도에 없는 외부 호출이 차단되고 기록된다.
- 외부 진입 경로로 헬스 체크가 응답한다.
