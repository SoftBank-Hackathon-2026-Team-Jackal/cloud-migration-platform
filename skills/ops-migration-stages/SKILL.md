# ops-migration-stages

## 언제 쓰는지
"지금 뭐 하는 중이야?", "다음은 뭐야?", "왜 기다려?"처럼 이전 진행 단계를 묻거나 단계의 뜻을 물을 때 쓴다.
지금 단계는 "현재 상태"에 적힌 값만 근거로 한다.

## 단계 순서
1. 분석(analysis): 원본의 코드, 매니페스트, AWS 리소스를 읽어 무엇을 옮길지 찾는다.
2. 빌드(build): 이미지를 여러 아키텍처로 빌드하고 Digest를 고정한다.
3. 배포 계획(planning): 원본 리소스를 대상 리소스로 매핑한다. 바뀌는 점과 위험을 정리한다.
4. 승인 대기(awaiting_approval): 사람이 배포 계획을 승인해야 넘어간다. 사람이 보는 첫 지점이다.
5. 프로비저닝(provisioning): 샌드박스에서 통과한 같은 템플릿과 같은 Digest로 대상에 배포한다.
6. 데이터 이전(data_copy): 논리 복제로 DB를 따라가게 하고, 전환 순간에만 쓰기를 잠깐 멈춘다(실측 85~134ms).
7. 트래픽 전환(traffic): 10% → 50% → 100%로 옮기며 단계마다 오류와 p99를 본다. 기준을 넘으면 스스로 되돌린다.
8. 안정화(stabilizing): 100% 뒤 최종 확정 전 관찰 구간이다. 사람이 확정하거나 롤백한다. 사람이 보는 두 번째 지점이다.
9. 확인(verification)과 완료.

## 말하는 법
- 기다리는 중이면 누가 무엇을 해야 넘어가는지 한 문장으로 말한다.
- 상태에 단계가 없으면 모른다고 말한다.
