# Ticket 35 — 워커 쪽 레드팀 Agent 역할과 Tool 경계

## 상태
DRAFT — 사용자 검토 대기. Issue #334. 선행: 33, 34. 결정: [ADR-008](../../docs/decisions/ADR-008.md) R1.

## 목적
레드팀 판단을 기존 에이전트 런타임(08A, Mapper·Tester·Fixer와 같은 구조) 안의 새 역할로 두고, **Tool 경계와 비용 상한 안에서만** 동작하게 한다. Pod는 실행기일 뿐 판단하지 않는다.

## 관련 요구사항
AV-024, AV-007, AV-020, ADR-004

## 선행 작업
Blocked by: 33, 34, 08A·20(병합됨)

## 범위
- 포함
  - 역할 정의와 Skill 형식(08A): 입력은 마스킹된 요구사항·`network_intent`·Finding 요약, 출력은 구조화된 다음 행동(허용 목록의 항목 이름과 인자)
  - **Tool 허용 목록:** 코드로 강제한다. 목록 밖 항목, 임의 명령, 파일·네트워크 직접 접근은 거절한다. 어떤 항목을 목록에 넣을지는 사용자가 확정한다(이 티켓은 목록 모델과 강제까지)
  - **신뢰할 수 없는 입력:** 대상 앱의 응답은 데이터로만 다루고 지시로 해석하지 않는다. 응답 본문은 마스킹 후 구분된 필드로만 모델에 전달한다
  - 턴 수·토큰·시간 상한(ADR-004 비용 상한 재사용), 상한 도달 시 지금까지의 Finding을 보존하고 종료
  - 의사결정 근거를 마스킹해 Finding과 함께 남김(재현성)
  - 실행기 호출은 워커가 Kubernetes API로 한다. Pod와 모델 사이의 직접 통신은 없다
- 제외: 목록에 들어갈 구체적 시험 항목의 정의, 수정 연계(36)

## 수용 기준
- [ ] 허용 목록 밖 행동을 요청하는 모델 출력(가짜 LLM)은 실행되지 않고 사유가 기록된다
- [ ] 대상 응답에 지시문처럼 보이는 텍스트가 있어도 행동 선택이 바뀌지 않는다(고정 fixture)
- [ ] 상한 도달 시 종료하고 Finding·정리·초기화가 보존된다
- [ ] 모델에 전달되는 모든 텍스트에서 비밀 값이 마스킹되어 있다(전달 직전 검사)
- [ ] 모델 입력은 그레이박스(R7)다: 경로 목록(메서드·경로·파라미터 이름)과 마스킹된 요구사항만 들어가고 소스 코드와 `.env` 값은 들어가지 않는다. 심어 둔 취약점 정답지는 입력 어디에도 없다(입력 구성 단위 시험으로 고정)
- [ ] Pod에서 외부(모델 API 포함)로 나가는 경로가 없다
- [ ] 도구 호출 스키마에 호스트·URL·IP 인자가 없다(요청 경로만 선택). 모델 출력에 다른 호스트가 들어 있어도 실행되지 않고 `OUT_OF_SCOPE_TARGET`으로 기록된다(가짜 LLM에 외부 사이트 주소를 요청하게 하는 시험으로 고정)
- [ ] 대상 앱이 응답으로 다른 주소로 요청을 보내라고 유도해도(앱 안에서 외부로 나가려는 요청 포함) 외부 차단(34)으로 나가지 않고 차단 기록이 남는다
- [ ] Agent 입력에는 경로 목록만 있고 소스코드·`.env`·비밀 값이 없다(전달 직전 검사). 정답지(심어 둔 취약점 목록)는 입력·프롬프트 어디에도 없다

## Test Seam
- 순수: 허용 목록 검사, 입력 구성(마스킹·구분)
- 서비스: 가짜 LLM + `FakeRunner`로 경계 위반·상한·종료 처리
- 실제 모델: 사용자 승인 후 1회(비용 발생)
- 놓치는 것: 실제 모델 판단 품질
